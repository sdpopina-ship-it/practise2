# Визуализатор зависимостей npm

Практическая работа №2 по дисциплине «Конфигурационное управление»,
вариант 20. Реализованы этапы 1-3: TOML-конфигурация, получение данных npm
и рекурсивное построение графа зависимостей.

## Параметры конфигурации

Приложение получает настройки только из TOML-файла. Проверяются все
параметры варианта:

- `package_name` — непустое имя пакета;
- `repository` — HTTP(S)-адрес реестра npm либо путь к файлу тестового
  репозитория;
- `use_test_repository` — режим выбора источника данных;
- `package_version` — непустая версия пакета;
- `ascii_tree` — необходимость ASCII-дерева;
- `max_depth` — положительная максимальная глубина анализа.

Если `use_test_repository = true`, значение `repository` должно вести к
существующему файлу. Если режим выключен, требуется HTTP(S)-адрес.

## Возможности этапа 2

Приложение формирует HTTP-запрос к API npm в виде:

```text
<repository>/<package_name>/<package_version>
```

Из JSON-ответа извлекается объект `dependencies`: это прямые зависимости
заданной версии пакета. Каждая зависимость выводится как `имя: диапазон`.
Используются только модули стандартной библиотеки Python: `urllib` и `json`.
Команда npm и сторонние библиотеки не используются.

## Возможности этапа 3

Граф строится алгоритмом DFS с рекурсией. Корневой пакет имеет глубину 0,
а узлы на значении `max_depth` добавляются в граф без раскрытия потомков.
Это исключает появление вершин глубже заданного ограничения.

Для защиты от циклических зависимостей используется множество активных
узлов рекурсии. Ребро цикла сохраняется в графе, но повторный обход уже
активной вершины не запускается.

При `use_test_repository = true` приложение читает JSON-файл графа. Имена
тестовых пакетов должны быть одиночными заглавными латинскими буквами, а
каждая зависимость должна ссылаться на объявленный пакет.

В `examples/` подготовлены три варианта тестового репозитория:

- `test_repository.json` — обычный граф с общей транзитивной зависимостью;
- `test_repository_cycle.json` — граф с циклом `A -> B -> C -> A`;
- `test_repository_depth.json` — цепочка для проверки `max_depth`.

## Структура

```text
src/        исходный код
tests/      автоматические тесты
examples/   рабочая TOML-конфигурация и тестовый репозиторий
scripts/    сценарии демонстрации тестовых графов
run.sh      скрипт запуска
```

## Запуск

Требуется Python 3.11 или новее: модуль `tomllib` входит в стандартную
библиотеку, сторонние зависимости не нужны.

```bash
./run.sh
./run.sh --config examples/config.toml
python3 -m src.main --config examples/config.toml
./scripts/run_stage3_examples.sh
```

Пример результата для `express@4.21.2`:

```text
Граф зависимостей express@4.21.2:
express@4.21.2 -> accepts@~1.3.8, array-flatten@1.1.1, ...
accepts@~1.3.8 -> (нет зависимостей в пределах глубины)
...
```

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют конфигурацию, npm-клиент, рекурсивный DFS, циклы,
ограничение глубины, формат тестового репозитория и консольный вывод.
