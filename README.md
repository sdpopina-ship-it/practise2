# Визуализатор зависимостей npm

Практическая работа №2 по дисциплине «Конфигурационное управление»,
вариант 20. Проект будет строить и визуализировать граф зависимостей npm.
Сейчас реализован только этап 1: чтение и проверка конфигурации.

## Возможности этапа 1

Приложение получает настройки только из TOML-файла и при корректном запуске
выводит их в формате `ключ = значение`.

Проверяются все параметры варианта:

- `package_name` — непустое имя пакета;
- `repository` — HTTP(S)-адрес реестра npm либо путь к файлу тестового
  репозитория;
- `use_test_repository` — режим выбора источника данных;
- `package_version` — непустая версия пакета;
- `ascii_tree` — необходимость ASCII-дерева;
- `max_depth` — положительная максимальная глубина анализа.

Если `use_test_repository = true`, значение `repository` должно вести к
существующему файлу. Если режим выключен, требуется HTTP(S)-адрес.

## Структура

```text
src/        исходный код
tests/      автоматические тесты
examples/   рабочая TOML-конфигурация и тестовый репозиторий
run.sh      скрипт запуска
```

## Запуск

Требуется Python 3.11 или новее: модуль `tomllib` входит в стандартную
библиотеку, сторонние зависимости не нужны.

```bash
./run.sh
./run.sh --config examples/config.toml
python3 -m src.main --config examples/config.toml
```

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют успешное чтение конфигурации и ошибки для каждого параметра.
